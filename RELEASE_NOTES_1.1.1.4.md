# Release Notes — v1.1.1.4

## Version 1.1.1.4 (2026-11-14) — Robustness fixes and per-host skill identity

### Summary
`hermes-oracle-memory` v1.1.1.4 closes issues #5–#12. Writes made during an ONNX cooldown are kept instead of lost, pool and transaction failures no longer leak sessions or retry inside a dead transaction, the recall path does fewer round trips and ranks before it cuts, the tool surface has hard limits, and the shared skill corpus gets a per-host identity so one host can no longer delete or overwrite another host's copy of a skill.

### Why
1. **Skill copies of different hosts collided (#5).** Rows were keyed by skill name only. A sync or an `archived` event on one host deleted the rows another host had written for the same skill, and pruning matched by path prefix across hosts.
2. **The lifecycle hook ran on the caller's thread (#6).** File lookup, hashing and the database write ran inside the skill tool call; an event that arrived while a write was running was dropped, and the hook searched the default skills dir instead of the active profile's.
3. **Writes during an ONNX cooldown were lost (#7).** `oracle_add` failed while the in-database model was cooling down, and the embedding backfill retried failed rows without backoff.
4. **Pool lifecycle (#8).** A re-`initialize()` replaced the pool without closing the old one, and `shutdown()` could close the pool while a background worker still used it.
5. **Transactional insert (#9).** After a failed statement the insert retried inside the same broken transaction, and `ORA-00060` (deadlock) started the 60 s ONNX cooldown.
6. **Recall path (#10).** A retry after `ORA-51815` reused the failed cursor, CLOB columns cost one round trip per row, fetch sizes ignored the result size, rows were cut to `top_k` before the final ranking, and the word "timeout" in any error text counted as a timeout.
7. **Tool surface (#11).** Batch adds and reads had no size caps, search returned whole documents, schemas missed parameters, the built-in memory mirror ignored `replace`/`remove`, generic tools could edit skill rows, and tag filters were case-sensitive.
8. **Packaging and scanner hygiene (#12).** Helper scripts read the Hermes env file unconditionally (two at import time), `pyproject.toml` used a non-SPDX license string, and the CLA allowlist matched any `*[bot]` account.

### What changed
- **Skill corpus identity (#5)**:
  - Rows are `skill:<host>:<name>:c<N>` with `metadata.host`. The host id is `HERMES_HOST_ID` when set, otherwise the short host name in lower case (the same with or without a `HOSTNAME` variable, so a shell and a service agree). `<name>` is the parsed skill name (frontmatter `name`, else the directory name), the same for the bulk sync and the lifecycle hook.
  - Profiles on one host share the host id, so they share one copy per skill name. Neither the lifecycle hook nor the bulk sync (not even with `force`) replaces a copy whose stored SKILL.md still exists outside the scanned skill dirs: the hook logs a warning, and the sync counts the copy in `skipped_foreign` / `foreign_skills`. This also applies to a sync over an explicit `--dirs` subset, for copies stored from the other roots. Profiles are not fully isolated, though: a skill dir that one profile links into another can still be rewritten and then archived or pruned by the second profile (#14). Set `HERMES_HOST_ID` per profile to keep profiles apart.
  - Stored SKILL.md paths are the in-root paths, not symlink targets, so a skill dir linked into a root is archived and pruned like any other. A copy counts as current only when its hash matches and it records where the skill lives now; a moved skill, or a pre-1.1.1.4 row recording a link target outside the roots, is rewritten once.
  - A bulk sync skips a skill only when this host's own copy, or an identical host-less shared-corpus copy, is current (for `mode=full`, one that holds the whole document); another host's copy no longer counts, since that host may archive it. The `mode` keyword of `sync_skills_library` is honoured (`oracle_sync_skills(mode="full")` and `--mode full` used to run a meta sync).
  - A host deletes or replaces only rows with its own id prefix (`memory_id LIKE 'skill:<host>:<name>:c%'`, LIKE wildcards escaped). Each changed skill is replaced in one transaction, so a failed write keeps the previous rows; a sync continues past a failed skill and reports `status: "partial"`.
  - Pruning is opt-in: `oracle_sync_skills(prune=true, prune_limit, dry_run)` or `sync_skills.py --prune` / `--prune-host <dir>`. It removes this host's skills whose SKILL.md is gone from the scanned roots and never touches other hosts or the host-less shared corpus.
  - Migration for existing rows: `sync_skills.py --list-local` prints a host's live skills; `--migrate-host-identity --listing <file> ...` relabels a legacy (host-less) skill only when exactly one host has a live SKILL.md at the stored path. It is a dry run unless `--apply` is given, checks the updated row count before committing, keeps the old id in `metadata.legacy_id`, and `--reverse-host-identity` undoes it. Skills whose files no longer exist on any host stay shared.
  - `oracle_load_skill fetch` keys copies by (host, path), takes an optional `host`, and bounds the rows per copy in SQL; `list` pages over distinct names (no repeats or short pages) and reports `copies`.
- **Lifecycle hook (#6)**: the hook validates the skill name, resolves the profile-aware skill roots and schedules work. One writer thread per skill and table in the process (whichever provider instance the event reached) does the lookup, hash check and write; events that arrive meanwhile are coalesced into one re-run with the latest event. The writer key is fixed when the work is scheduled, and an event that reached another provider runs on that provider's own thread, so its shutdown waits for it. The hook finds skills up to six levels below a root (the bulk sync walks any depth). `archived` deletes this host's copy only when no SKILL.md for the skill is left. It finds the copy by id or by its stored path, and keeps a copy whose stored SKILL.md still exists, such as a live skill under another directory, unless that file is the target of the symlink that was archived.
- **Cooldown writes and backfill (#7)**: during a cooldown a fact is stored with a NULL embedding and queued for backfill (text search finds it at once). Failed backfill batches back off exponentially (2 s to 300 s, 8 attempts); a startup scan re-queues rows that still have no embedding; `shutdown()` drains the queue within its time budget. A queued row keeps only its latest text, and the backfill writes a vector only while the row has none and still holds the text it was computed from (`DBMS_LOB.COMPARE`; text over 4,000 UTF-8 bytes is bound as a temporary CLOB, released at the commit, since a longer string bind fails in SQL with ORA-01460), so an update made meanwhile — on this host or another — is never overwritten with an outdated vector. A row the guard skips is re-read: if it still has no embedding, it is queued again with the text the database holds (bounded by the attempt limit), so a row whose stored text never matches the queued text is not silently left without a vector.
- **Pool lifecycle (#8)**: the old pool is retired on re-init and on the failed-init path (closed in the background if connections are still borrowed); `shutdown()` leaves the pool open, with a log line, if a worker is still busy past its budget.
- **Transactional insert (#9)**: inserts inside a caller's transaction use a savepoint and abort on a broken transaction instead of retrying; `ORA-00060` is a data error.
- **Recall path (#10)**: a fresh cursor per `ORA-51815` retry; CLOBs fetched as strings in the same round trip (`fetch_lobs=False`, lossless); `arraysize`/`prefetchrows` sized to the result; final ranking before the `top_k` cut; one hybrid text weight on all paths; timeouts classified by error code only.
- **Tool surface (#11)**: `oracle_add` takes at most 100 facts of 32,000 chars, inserted all-or-nothing; `oracle_get` enforces its limit; search output caps each result at 4,000 chars and includes tags; `oracle_chunk` validates `max_words` (10–1000); `skill:` rows are read-only for the generic tools (`oracle_add`, `oracle_update`, `oracle_delete` refuse `skill:` ids and never touch `role='skill'` rows); tag filters are case-insensitive; the memory mirror handles `add`, `replace` and `remove`; missing schema parameters added.
- **Hygiene (#12)**: helper scripts read `OCI_*` settings from the environment and load a KEY=VALUE file only with `--env-file` (environment values win); `license = "BUSL-1.1"` with `license-files` (setuptools ≥ 77); the CLA allowlist names its bots.
- Version bump `1.1.1.3` → `1.1.1.4` across `VERSION`, `plugin.yaml`, `pyproject.toml`, `__version__`, README/INSTALL badges, both `skills/*/SKILL.md` pins, `AGENTS.md` and `NEEDS.md` (both had drifted since 1.1.0.1; the version test now checks them). Release-notes rotation: `RELEASE_NOTES_1.1.1.3.md` → `RELEASE_NOTES_1.1.1.4.md` (v1.1.1.3 details remain in `CHANGELOG.md`).

### Upgrade notes
- **No schema change.** The host id lives in the existing `memory_id` and `metadata`.
- **Skill corpus migration** (optional, once per fleet): upgrade every host first, then run the migration from one host with a dry run, review the counts, and run it for real. New syncs write host-qualified rows either way; until the migration runs, legacy rows remain as a shared copy next to the new per-host copy.
- **Set `HERMES_HOST_ID`** if two hosts share a short host name, or per profile if profiles on one host must not share skill copies (see #14).
- **Helper scripts** no longer read an env file by themselves: export the `OCI_*` settings, or pass `--env-file <file>`.
- `oracle_add` with more than 100 facts, or a fact over 32,000 chars, is now an error instead of a partial insert.

### Known limitations

Tracked in #14, none blocking:
- Profiles that share a host id share skill copies (see the upgrade notes).
- `skipped_foreign` has no override flag.
- The lifecycle file lookup can treat a link into `.archive/` as live.
- The backfill re-queues mismatched rows during shutdown, and drops them silently when the driver cannot report row counts. The startup re-scan covers both.
- The test-suite symlink guard checks only the source text.
